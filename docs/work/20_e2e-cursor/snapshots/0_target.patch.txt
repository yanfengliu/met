+# Keep the test browser off the owner's cursor
+
+Status: active
+Owner: Claude Code desktop session cursor-lock-7e41a2 (2026-11-04)
+Created: 2026-11-04
+Updated: 2026-11-04
+
+## Problem and outcome
+
+The owner reported (2026-11-04): "What keeps moving my mouse? It is teleporting my mouse.", then "It is definitely something claude is doing". The cause is the e2e suite. Walk mode takes the pointer lock, and on Windows Chrome implements the lock on the one system cursor, headless or not: `DesktopWindowTreeHostWin::LockMouse` confines it with `::ClipCursor` to the page's screen rectangle inset 5 px, `MoveCursorToCenter` moves it with `::SetCursorPos`, and the unlock frees it and moves it again (Chromium's `render_widget_host_view_event_handler.cc` and `desktop_window_tree_host_win.cc`; headless Chrome on Windows still makes a real window, cloaked, `hwnd_message_handler_headless.cc`). Measured on 59313d0 with a probe of 6 locks and a cursor watch: 12 clip changes to the hidden 1280×720 window's rectangle and 12 jumps, to the box's centre on each lock and to (18, 65) on each unlock, at 150% display scale. Every session's `npm run verify`, and every direct `npx playwright test` of a spec that walks with the real lock, did this to the owner's cursor.
+
+Outcome: on Windows the e2e browser runs in a separate, non-interactive window station, where Windows refuses its cursor calls. The tests, the dev server and the reporters stay where they are and connect to it. A gate fails when the e2e browser confines the system cursor.
+
+## Scope
+
+Included: how the e2e browser starts (`playwright.config.ts`, a global setup, a browser server, the window-station launcher), a gate spec, unit tests for the launcher, and the records: AGENTS.md's gates, the defect register, the gate proof and the devlog.
+
+Excluded: headed and debug runs (`--headed`, `--debug`, `PWDEBUG`), which need a visible window and keep the browser on the desktop; `npm run shots` and `npm run sweep`, which never take the lock (`walk=1` leaves the pointer free until a click, and capture never clicks); hosts other than Windows, where nothing changes.
+
+## Approach
+
+The prototype (ignored `tmp/cursor-lock/`, its logs in `tmp/cursor-lock/evidence/`) compared three places for the browser under the gate lock, with a cursor watch outside it:
+
+| Where the browser ran | Locks granted | Clip changes | Jumps |
+|---|---|---|---|
+| The desktop, as before | 6 of 6 | 12 | 12 |
+| A hidden desktop in the interactive window station | 6 of 6 | 12 | 0 |
+| A hidden desktop in a separate, unnamed window station | 6 of 6 | 0 | 0 |
+
+A hidden desktop stops the moves, since `SetCursorPos` needs the input desktop, but not the confinement, which `ClipCursor` checks against the window station. Only administrators may name a window station, so the launcher asks for an unnamed one, which Windows names after the logon session. In it the GPU was still the RTX 4090 through Direct3D 11. With the whole Playwright run inside, the full suite passed (126 tests in 10.2 minutes) and `routes.spec` and `walk.spec` at 4× CPU throttle passed (21, 2 skipped), the watch seeing no clip change and no jump in 612 s and 151 s.
+
+Chosen: only the browser moves. A global setup starts `chromium.launchServer` inside the window station through `scripts/window-station.ps1` and gives its endpoint to the workers, which connect through `use.connectOptions`. So `npm run test:e2e`, `npm run verify` and a direct `npx playwright test` are covered alike, and the runner, the dev server and the reporters stay on the desktop with live output. The launcher puts the browser's process tree in a job that ends with the launcher, and the server closes Chrome when the runner's pipe closes. Tradeoff: the tests drive a connected browser instead of a launched one, so the whole suite through it is the acceptance check.
+
+## Acceptance criteria
+
+- On Windows a headless e2e run's browser cannot confine the system cursor: `tests/e2e/cursor.spec.ts` takes the real pointer lock and reads the cursor's clip from its worker on the desktop, and it is the whole screen. The spec fails with the browser started on the desktop.
+- The full e2e suite passes through the connected browser, and `routes.spec` and `walk.spec` pass at 4× CPU throttle, while a cursor watch sees no clip change and no jump.
+- `npm run verify` passes on the merged tree.
+- A run stopped midway leaves no browser or server running.
+- `--headed` and `PWDEBUG` runs start the browser on the desktop as before.
+- Independent review of the change, with its findings resolved.

+ * Starts a command where nothing it starts can confine or move the owner's cursor (work unit 20, docs/learning/defect-register.md).
+ *
+ * On Windows, Chrome's pointer lock confines the system cursor to the page (`ClipCursor`) and moves it (`SetCursorPos`), headless or not, and the e2e specs that walk take that lock.
+ * Windows refuses both to a program in a separate, non-interactive window station, which `scripts/window-station.ps1` makes and runs the command in; a hidden desktop in the interactive window station stops only the moves.
+ * `tests/e2e/global-setup.ts` starts the e2e browser there, `playwright.config.ts` connects the workers to it, and `tests/e2e/cursor.spec.ts` is the gate.
+ * Bound: `windowsCommandLine` quotes for programs that split their command line as the Microsoft C runtime does, as node.exe does; `browserPlace` decides only from what it is given.
+ */
+import { spawn } from 'node:child_process';
+import type { ChildProcess, StdioOptions } from 'node:child_process';
+import { join } from 'node:path';
+
+/** The PowerShell launcher that makes the window station and runs the command in it (its header says how). */
+export const WINDOW_STATION_LAUNCHER = join(import.meta.dirname, 'window-station.ps1');
+
+/** The variable that carries the e2e browser server's endpoint from the global setup to the workers. */
+export const TEST_BROWSER_ENDPOINT = 'MET_TEST_BROWSER_WS';
+
+/** Quotes one argument so that a program splitting its command line as the Microsoft C runtime does gets it back unchanged. */
+export function windowsArgument(arg: string): string {
+  if (arg !== '' && !/[\s"]/u.test(arg)) return arg;
+  let quoted = '"';
+  let backslashes = 0;
+  for (const ch of arg) {
+    if (ch === '\\') {
+      backslashes += 1;
+      continue;
+    }
+    // Backslashes are literal except before a quote, where each must be doubled and the quote itself escaped.
+    quoted += ch === '"' ? `${'\\'.repeat(backslashes * 2 + 1)}"` : `${'\\'.repeat(backslashes)}${ch}`;
+    backslashes = 0;
+  }
+  return `${quoted}${'\\'.repeat(backslashes * 2)}"`;
+}
+
+/** The Windows command line that runs `argv`, the program first. */
+export function windowsCommandLine(argv: readonly string[]): string {
+  return argv.map(windowsArgument).join(' ');
+}
+
+/** Where the e2e browser runs, and when it is the desktop, why. */
+export type BrowserPlace = { readonly place: 'window station' } | { readonly place: 'desktop'; readonly reason: string };
+
+/**
+ * The e2e browser runs in a separate window station on Windows, unless the run shows it: a headed run, a `PWDEBUG` run, or `MET_E2E_DESKTOP=1`, the way out for a host
+ * where the window station cannot be made. On the desktop its pointer lock confines and moves the cursor again.
+ */
+export function browserPlace(platform: NodeJS.Platform, headless: boolean, env: NodeJS.ProcessEnv): BrowserPlace {
+  if (platform !== 'win32') return { place: 'desktop', reason: 'the separate window station is a Windows mechanism; elsewhere Playwright launches the browser itself' };
+  if (!headless) return { place: 'desktop', reason: 'a headed run shows its browser, on the desktop, where its pointer lock confines and moves the cursor' };
+  if ((env['PWDEBUG'] ?? '') !== '') return { place: 'desktop', reason: 'a PWDEBUG run shows its browser and the inspector, on the desktop' };
+  if (env['MET_E2E_DESKTOP'] === '1') return { place: 'desktop', reason: 'MET_E2E_DESKTOP=1 asks for the browser on the desktop' };
+  return { place: 'window station' };
+}
+
+/**
+ * Starts `argv`, the program first, in a separate, non-interactive window station through `scripts/window-station.ps1`, in `cwd`, with this process's environment
+ * and the standard streams `stdio` names. The returned process is the launcher's, and its exit status is the command's; ending it ends the command and all it started.
+ */
+export function startInWindowStation(argv: readonly string[], cwd: string, stdio: StdioOptions): ChildProcess {
+  return spawn('powershell.exe', ['-NoProfile', '-NonInteractive', '-ExecutionPolicy', 'Bypass', '-File', WINDOW_STATION_LAUNCHER], {
+    cwd,
+    stdio,
+    env: { ...process.env, MET_WINDOW_STATION_COMMAND: windowsCommandLine(argv) },
+    windowsHide: true,
+  });
+}
+
+/** The workers' connection to the e2e browser server the global setup started, or none when it started none, as before it has run. */
+export function testBrowserConnection(env: NodeJS.ProcessEnv): { readonly wsEndpoint: string } | undefined {
+  const wsEndpoint = env[TEST_BROWSER_ENDPOINT] ?? '';
+  return wsEndpoint === '' ? undefined : { wsEndpoint };
+}

+/**
+ * Starts the e2e browser where its pointer lock cannot confine or move the owner's cursor (work unit 20, docs/learning/defect-register.md).
+ *
+ * On Windows, Chrome's pointer lock confines the system cursor to the page and moves it, headless or not. Unless the run shows its browser (scripts/window-station.ts
+ * `browserPlace`), this starts the browser as a Playwright browser server (tests/e2e/browser-server.ts) in a separate, non-interactive window station, where Windows
+ * refuses those calls, and sets MET_TEST_BROWSER_WS before the workers start; each worker reads it in playwright.config.ts and connects instead of launching.
+ * The runner, the dev server and the reporters stay on the desktop. The teardown ends the server's standard input, which closes the browser, then ends the launcher
+ * if it lingers, which ends the job and everything in it.
+ * Bound: one server per run, given 60 s to start and 15 s to close; tests/e2e/cursor.spec.ts is the gate.
+ */
+import type { ChildProcess } from 'node:child_process';
+import { join } from 'node:path';
+import { setTimeout as delay } from 'node:timers/promises';
+
+import type { FullConfig } from '@playwright/test';
+
+import { browserPlace, startInWindowStation, TEST_BROWSER_ENDPOINT } from '../../scripts/window-station.js';
+
+const SERVER = join(import.meta.dirname, 'browser-server.ts');
+const START_MS = 60_000;
+const CLOSE_MS = 15_000;
+
+/** Reads the server's endpoint line, failing with what it said on standard error if it ends or gives none in time. */
+function endpointOf(server: ChildProcess): Promise<string> {
+  return new Promise((resolve, reject) => {
+    let out = '';
+    let err = '';
+    let settled = false;
+    const settle = (endpoint: string | undefined, why: string): void => {
+      if (settled) return;
+      settled = true;
+      clearTimeout(timer);
+      if (endpoint !== undefined) {
+        resolve(endpoint);
+        return;
+      }
+      server.kill();
+      reject(
+        new Error(
+          `The e2e browser did not start in a separate window station: ${why}.${err === '' ? '' : ` It said: ${err.trim()}`} ` +
+            'Set MET_E2E_DESKTOP=1 to start it on the desktop instead, where its pointer lock confines and moves the cursor.',
+        ),
+      );
+    };
+    const timer = setTimeout(() => {
+      settle(undefined, `no endpoint within ${String(START_MS / 1000)} s`);
+    }, START_MS);
+    server.stdout?.setEncoding('utf8').on('data', (chunk: string) => {
+      out += chunk;
+      for (const line of out.split('\n')) {
+        if (!line.startsWith('{')) continue;
+        try {
+          const parsed: unknown = JSON.parse(line);
+          if (typeof parsed === 'object' && parsed !== null && 'wsEndpoint' in parsed && typeof parsed.wsEndpoint === 'string') settle(parsed.wsEndpoint, '');
+        } catch {
+          // A partial line; the rest comes with the next chunk.
+        }
+      }
+    });
+    server.stderr?.setEncoding('utf8').on('data', (chunk: string) => {
+      err += chunk;
+      process.stderr.write(chunk);
+    });
+    server.on('error', (error) => {
+      settle(undefined, `the launcher could not start (${error.message})`);
+    });
+    server.on('exit', (code) => {
+      settle(undefined, `the launcher ended with status ${String(code)}`);
+    });
+  });
+}
+
+/** Ends the server's standard input, which closes the browser, and ends the launcher, and so its job, if it has not ended in time. */
+async function stop(server: ChildProcess): Promise<void> {
+  if (server.exitCode !== null || server.signalCode !== null) return;
+  const exited = new Promise<void>((resolve) => {
+    server.once('exit', () => {
+      resolve();
+    });
+  });
+  server.stdin?.end();
+  const ended = await Promise.race([exited.then(() => true), delay(CLOSE_MS).then(() => false)]);
+  if (!ended) {
+    server.kill();
+    await exited;
+  }
+}
+
+export default async function globalSetup(config: FullConfig): Promise<(() => Promise<void>) | undefined> {
+  const headless = config.projects.every((project) => project.use.headless !== false);
+  if (browserPlace(process.platform, headless, process.env).place === 'desktop') return undefined;
+  const channel = config.projects[0]?.use.channel ?? '';
+  const server = startInWindowStation([process.execPath, SERVER, channel], config.rootDir, ['pipe', 'pipe', 'pipe']);
+  process.env[TEST_BROWSER_ENDPOINT] = await endpointOf(server);
+  return async () => {
+    await stop(server);
+  };
+}
