# The collection on view

Placeholders of real objects on view in the model's spaces, built from The Met's collection data (owner, 2026-10-25: "put some placeholder artifacts in the museum"; "you can try to use met api to get the real things too"). The decision recorded in AGENTS.md's non-goals: artworks are procedural placeholders of real objects on view, built from The Met's CC0 collection data, which a script fetches by hand and never at runtime; colours sampled from a public-domain object's image are data, not a photo texture. Plan: `docs/work/2_doors-and-collection/plan.md`, milestone M3a; the read-only survey behind the picks is worker `met-api`'s of 2026-10-25 (evidence in `tmp/met-api/`, ignored).

## Source and licence

- The Met Collection API, https://metmuseum.github.io/ (viewed 2026-10-25). An object's record is `GET https://collectionapi.metmuseum.org/public/collection/v1/objects/{id}`: title, maker, date, medium, object name, classification, department, credit line, `GalleryNumber`, `isPublicDomain`, `primaryImageSmall`, a `dimensions` text and `measurements`, a list of elements (Overall, Framed, Pedestal, ...) each measured in centimetres (and kilograms).
- Search: `v1/search` has answered HTTP 410 since 2026-10-01 ("use /public/collection/v1.1/search, which is Elastic-backed and paginated via offset and limit"). `v1.1/search` filters by `isOnView`, `departmentId`, title, artist and more, but not by gallery, so the survey narrowed by department and name and then read each record's `GalleryNumber`, which can be empty even for an object on view.
- Licence: the metadata is CC0 ("select datasets of information on more than 470,000 artworks ... Creative Commons Zero", the API's documentation). Images are given only for public-domain records (`isPublicDomain` true); for the others `primaryImage` and `primaryImageSmall` are empty. The model uses no image as a texture and commits none: the script samples colours from public-domain images only, and keeps the images in its ignored cache.
- At runtime the page fetches nothing (`tests/e2e/network.spec.ts`): images.metmuseum.org drops its CORS header on cached responses, so a deployed page could not use the images anyway (the survey's check, 2026-10-25).
- Pace: the API documents 80 requests a second, but its CDN (Imperva) blocked the survey with HTTP 403 pages after about 130 requests at about 4 a second, for about 8 minutes; 572 requests at one a second then ran without a block. The script makes at most one request a second.

## Regenerating

Run `npm run met-catalogue` by hand (never in CI or the build). It reads `src/model/collection/picks.ts`, fetches each pick's record and, for a public-domain record with an image, that image, through a cache in `research/cache/met-api/` (ignored; one `.json` of metadata and one `.body` per URL), so a rerun asks the network only for what it has not seen. It decodes each image in the system Chrome through Playwright (createImageBitmap and canvas `getImageData`, sRGB; no image library) into 64 × 64 bins of summed pixels, builds one entry per pick by the rules below (`scripts/met-catalogue-rules.ts`), and writes `src/model/collection/catalogue.ts` once, through a temporary file renamed over it.

All or nothing: a problem with any pick (fewer than 5 or more than 12 in a space, fewer than 8 spaces, an object picked twice), a record that is not JSON or not the object asked for, a gallery mismatch, a missing height or a size out of 5 mm..25 m is listed with its object and its fix, and nothing is written (exit 1). HTTP 403 or 429 stops the run at once (exit 2) with what happened, when, and when to retry (the response's Retry-After, else 10 minutes later); every response cached before it is kept. The first run, on 2026-10-25, made 183 requests in about three minutes without a block.

Each entry keeps its provenance: the record's API URL, the day it was fetched, its `metadataDate`, and the first 16 hex digits of the SHA-256 of the response body; for a sampled image its URL, the hash of its bytes and its size in pixels. `CATALOGUE_SOURCE` names the API, the licence, the day the file was written, the script and the sampler's version (with the Chrome version that decoded the images). `scripts/fixtures/met-api/` keeps nine records as the API returned them (CC0), which `scripts/met-catalogue.test.ts` normalizes against values worked out by hand.

## Rules

Measurements. Of a record's measurement elements with a height, width, depth, length or diameter, those that name a frame, pedestal, base, mount, stand, case, foot or display are left out unless they measure the object without one ("Other (without base)", "Overall (without frame)"). Chosen, in order: 'Overall' with no description; one without its frame or base; 'Overall' with a description; one whose description says overall; the first left. Axes it lacks come from the others left (records that give height and width as separate 'Other' elements). Height is the record's Height; width is Width, else Diameter; depth is Depth, else Length, else Diameter. Centimetres become metres to the millimetre. A record whose measurements give no height is read from its `dimensions` text: the leading segments (split on ';') that start H., W., D., L., Diam. or Wt., each value from its "(… cm)", stopping at the first other segment, where a record starts on its parts ("helmet (a); H. …"). A record with neither needs a height in its pick. A pick may override any dimension (with its reason); every value must lie in 5 mm..25 m. Where only the height is known the other dimensions are estimates, marked `estimate` in `sizeFrom`: width 0.38 h for a figure (0.3 of its depth when that is longer than its height: a recumbent animal), 0.75 h for a bust, 0.62 h for a vessel, 0.8 h for a slab or a frame, 0.7 h for a block; depth 0.3 h for a figure, 0.55 h for a bust, a vessel's width, 0.12 h for a slab, 0.7 h for a block, and 5 cm for a painting. A record's Pedestal element (all three axes) becomes the plinth; a painting's Framed element gives its frame.

Kinds, from the object name and classification (the title only for a figure), first match wins: a painting (classification Paintings, or a painting, altarpiece, triptych or diptych) is a `frame`; an armour for a man (classification Armor…, name armor, garniture or Rennzeug) a `figure`, another piece of armour a `slab`; a name starting statue, statuette, figure or group a `figure`; vase, jar, bowl, amphora, krater, hydria, kylix, vessel, ewer, basin, urn, cup, lekythos, pitcher, bottle, dish, plate, tureen, censer or incense burner a `vessel`; a name starting head, or a bust, a `bust`; relief, stela, plaque, panel, slab, lintel, shield, akroterion, tapestry or textile a `slab`; capital, column, chest, sarcophagus, coffin, drum, canoe, chariot or mastaba a `plinth` (a block); statue, statuette, figure, group, sculpture, sphinx, lion, crab, deity, armour, garniture or pole anywhere in the name, classification or title a `figure`; anything else a block. A pick may override the kind.

Display, from the kind and size: a frame hangs on a wall; anything whose largest dimension is under 0.6 m stands in a vitrine; a slab from 0.6 m hangs on a wall; the rest stand on plinths. A pick may override it (and `floor` stands an object on the floor). Derived for the placeholders (`src/model/collection/place.ts`): a plinth 0.1 m wider than the object each way (at least 0.45 m), 0.2..0.8 m high under a block, 0.2..0.6 m under a long figure, else 1.4 m less half the object's height within 0.25..1.0 m, unless the record gives a pedestal or the space sets the height; a vitrine on a 0.9 m base with a glass case 0.15 m clear round the object (at least 0.4 m square) and 0.18 m over it; a hung frame 1 cm off its wall with its centre at 1.6 m, or higher so its bottom clears 0.5 m, within a ceiling the space names; a frame border from the Framed element, else 0.04 m plus 0.05 of the painting's smaller side, 0.05..0.16 m.

Forms (`src/model/collection/kinds.ts`), each filling a unit box that the piece's matrix scales to the object's size: a standing figure; a group, two figures side by side, when a figure is wider than 0.7 of its height; a recumbent figure when its depth or width exceeds 1.15 of its height; a bust; a jar, or a dish when a vessel's height is under 0.6 of its width; a relief panel; a block; a canvas whose front face shows the painting's 8 × 8 colour grid.

Colours. Only a record that is public domain and has an image is sampled; anything else falls back by its medium (first match: gilt or gold #b8954a, bronze, brass or copper #6f5434, silver #b9bcbd, steel or iron #7d8287, marble or alabaster #ddd7cb, granite, basalt, diorite or greywacke #5e5a57, limestone or sandstone #c2ab86, terracotta or earthenware #b06a45, porcelain, stoneware or ceramic #e4e2da, wood #76563a, oil, tempera or canvas #6a5a43, plaster #e8e3d8), else by kind. From an image: a painting's and a relief's colour is the whole image's mean (photographed face on, they fill it), and a painting also keeps 8 × 8 cells of the image, row by row from the top. For any other object the backdrop is every colour the image's top and side borders show (two bins deep, so a gradient backdrop and the shadows in it all count; the bottom edge is left out, where an object stands or is cut off); the object is the bins of the image's middle (the middle half across, three quarters up) farther than 30 (Euclidean, 0..255 a channel) from each of those colours, or the whole middle when they hold under 5 % of it; its colour is the mean of the brighter half of its pixels, near the colour it shows in light rather than in shade. An object photographed where it stands, the colour of its surroundings, can be lost in them; the colours are derived, and `colourFrom` says which rule gave each (`image`, `medium` or `kind`).

The page turns the catalogue's sRGB colours to linear and draws every artwork of a step with one shared material, which finds each instance's colour by its plan position in a small table (`src/model/collection/material.ts`), so the 94 objects' 259 pieces take 38 meshes and 40,290 triangles, not a mesh each (the whole model: 729 meshes, 1,578,714 triangles).

## Limits

- The placeholders are forms, not likenesses: a standing figure, a group, a recumbent figure, a bust, a jar or dish, a panel, a block, a canvas, each at the object's size and colour.
- Gallery 600 is 5.63 m high in the model (`GALLERY_CEILING_Y`, an estimate), so the Triumph of Marius's frame is 1.6 cm wide; the real room is taller.
- The way from the top of the Grand Staircase into gallery 600 is M1's (worker `walk2`): until it is merged the placement test restates its route R5 (on the axis from the nave's west side to the middle of 600), its doorway (X ±2.05, Z −70.0..−66.79) and its Dendur gate threshold (X 131.5..135.5, Z −71..−64) from walk2's plan, and keeps 1 m clear of each.
- The Rockefeller Wing (Asmat poles and canoe, not public domain), the Astor Court (no object names gallery 217), the Great Hall's eagle (11013, "in Great Hall") and the Egyptian galleries on route R3 were left for later: ten spaces met the plan's eight.
